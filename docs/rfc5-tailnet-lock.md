# RFC-5: Tailnet lock (TKA)

**Status:** Implemented (September 2026): stages 1 and 2 as a verifying
node; signing and fork resolution are not done (see "Not done").

## Problem

Our ionskale fork supports tailnet lock (`/machine/tka/*`, "tailnet lock"
in its changelog):
- trusted signing keys must sign every node key;
- nodes drop peers whose key signature does not verify.

Our client does none of this, which fails two ways:
1. **Locally.** In a locked tailnet, peers will not talk to our unsigned
   node. It "joins" but reaches nothing, with no error.
2. **Security.** We do not verify peers' `KeySignature`s, so a compromised
   control server could inject peers that locked-tailnet clients would reject.

## Proposal

Two stages.

**Stage 1 (small, do first): detect and refuse.**
- Parse `TKAInfo` from the map response, and the `KeySignature` of the self
  node and the peers.
- When the tailnet is locked and our node key has no signature, fail with a
  new `MeshError::LockedOut`, telling the operator to sign the node with its
  node key. meshd reports it as the code `locked_out`, and fakts surfaces it.

**Stage 2: be a proper TKA node.**
- **Sync:** send `TKAHead` in map requests and sync AUMs through
  `/machine/tka/sync/offer` and `sync/send`. Store the authority state (the
  chain of AUMs) next to `identity.json`.
- **Verify** each peer's `NodeKeySignature` (CBOR, ed25519, possibly
  rotation-wrapped) against the trusted keys, and drop peers that do not
  verify: no WireGuard session, no paths.
- **Optionally sign.** Holding a trusted key, the node could sign new nodes,
  like `tailscale lock sign`. Leave that to tooling.

The formats are in `tailscale.com/tka` (AUMs, CBOR, signature kinds). As with
the rest of the client, take test vectors from the Go code (the harness
already builds from `tailscale.com`).

## Tests

- **Harness:** enable lock on the test control server (testcontrol supports
  TKA) with an unsigned node, and expect `LockedOut` (stage 1).
- **Stage 2:**
  - a signed node joins, and a peer with a forged signature is dropped;
  - AUM chain vectors are generated by a Go test in the harness module.
- **Lab:** `ionscale tailnets enable-tailnet-lock` against ionskale.

## Done

**Core** (`src/tka.rs`, sans-IO):
- A strict reader for the CBOR subset Go writes: no indefinite lengths, no
  tags, no duplicate keys, depth ≤ 16.
- Hashes are taken over the bytes as received, so they match Go byte for
  byte without a canonical encoder. For a signature hash, the signature
  field (23 for AUMs, 4 for node-key signatures) is dropped at the byte level.
- AUMs are validated (Go's `StaticValidate`), verified (every signature by a
  key of the current state) and applied (add, remove and update key,
  checkpoint, no-op).
- `Authority`:
  - bootstraps from a checkpoint genesis, adopting its state as Go does;
  - `inform` takes updates in any order, as long as they form one line;
  - `sync_offer` gives head plus ancestors, ending at the oldest AUM;
  - `restore` re-verifies a saved chain.
- Node-key signatures: direct, rotation and credential. As in Go, a bare
  credential is refused: it authorizes a node only wrapped in a rotation
  signature by its wrapping key. The node key is
  compared in Go's `"np"`-prefixed binary form. Rotation signatures also give
  the keys they replaced (`previous_node_keys`).
- Disablement (Argon2i, 16 MiB) sits behind the default feature
  `tka-disable`. Small builds leave it out and stay locked (fail-closed) when
  a tailnet's lock is disabled.

**Driver** (`driver/lock.rs`, `node.rs`):
- The map stream keeps `TKAInfo`, and peers keep `KeySignature` (also from
  `PeersChangedPatch`) and `UnsignedPeerAPIOnly`.
- On a new head the node bootstraps (`/machine/tka/bootstrap`) and syncs
  (`sync/offer`, then `sync/send`; a missing `sync/send` is not an error).
  It syncs on a copy, so the loop keeps filtering with the last verified lock.
- Every applied netmap hides peers whose signature does not verify.
  - They move to `NetMap::untrusted`, invisible to every lookup, with no
    tunnel and no paths. Patches still reach them, so a peer signed later
    comes back.
  - Verdicts are cached per peer (key, signature, head), so a delta does not
    re-verify every signature.
- Fail-closed: control announces a lock that cannot be fetched or verified,
  so no peer is trusted (`LockStatus::Unverified`).
- Map requests carry our `TKAHead`.
- `Node::lock_status()`: `Unlocked`, `Locked { head, trusted_keys,
  hidden_peers, locked_out }` or `Unverified`.
- `Node::start_with_lock_store` persists the chain. `Session` keeps it in
  `tka.json` next to `identity.json`, so a restarted node does not take a new
  genesis from control.
- A locked-out node keeps running (signing its key fixes it without a
  restart). `Session`, meshd, fakts and Python report
  `SessionError::LockedOut`, code `locked_out`, Python `LockedOut`, naming
  the `nodekey:` to sign.

**Tests:**
- `tests/tka.rs`: vectors made by tailscale's own `tka` package
  (`tests/harness/tka_vectors_test.go`). They cover:
  - AUM hashes and signature hashes;
  - a chain of add, update and remove key, arriving at Go's head and keys;
  - updates in any order, gaps, tampering, and restore;
  - direct, rotation and credential signatures, a removed key, a forged
    signature, a bare credential, and disablement.
- `tests/lock.rs`: tailscale's test control server in the harness's new lock
  mode, where the Go peer runs `TailnetLockInit` and signs on request. It
  covers:
  - locked out until signed, then reaching the peer;
  - unsigned peers hidden;
  - a `Session` refused with `locked_out` that keeps its chain and starts once
    signed.
- `tests/lab_lock.rs`: ionskale's `lab-lock` tailnet, locked by a real
  tailscaled (`lab.sh lock`, signing with `lab.sh lock-sign`). It covers:
  - refused, signed, then a restart with neither key nor url on the saved chain;
  - signed nodes reaching each other;
  - an unsigned node hidden from them and unable to connect.

## Not done

- **Forks.** Updates must extend our head in one line; a fork is refused, and
  we keep the last verified state. Go resolves forks by weight, then
  remove-key, then hash. Add that if forks show up in practice.
- **Rotation-obsoleted peers.** Go also hides peers whose key a newer
  rotation signature replaced, and dedupes clones with the same wrapping key.
  We verify rotation signatures but do not yet drop the keys they replaced.
- **Compaction** of the stored chain. Chains are short in practice.
- **Signing** and **authoring AUMs** (`tailscale lock sign/add/remove`). Use
  tailscale for administration.
- **ESP32 persistence.** A bare `Node` keeps the chain in memory. The
  firmware should implement `LockStore` over NVS, and until then it takes the
  genesis from control on each boot.
- **Ed25519 edge cases.** Go verifies direct signatures with ZIP-215
  (`ed25519consensus`); we use `verify_strict`, which is stricter on
  non-canonical encodings. Honest signatures verify the same. A crafted edge
  case could be accepted by Go and refused by us, never the other way round.
